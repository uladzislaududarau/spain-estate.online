# Google Sheets для заявок Spain Property for Sale

[Подтверждено] Интеграция подготовлена для Cloudflare Worker и Google Apps Script. До настройки Google канал выключен: `GOOGLE_SHEETS_ENABLED=false`. Работа D1 и email продолжается.

[Подтверждено] В таблицу записывается одна строка на заявку: ID, местные дата и время, часовой пояс, имя, способ связи, контакт, язык, регионы, цель, тип объекта, бюджеты, срок покупки, согласие и его дата/версия, время создания UTC, источник. Заголовки столбцов стабильны для последующего импорта в CRM.

## Настройка владельцем

1. Создать закрытую таблицу «Spain Property for Sale — Лиды» в выбранном Google-аккаунте. Сохранить её ID из URL между `/d/` и `/edit`.
2. Создать проект Google Apps Script. Вставить `Code.gs`, добавить manifest `appsscript.json` из этой папки. Ключей в этих файлах нет.
3. В Project Settings → Script properties добавить `SPREADSHEET_ID`. При необходимости `SHEET_NAME=Лиды`.
4. Выполнить `setup` от имени владельца. Google запросит разрешение доступа к таблицам: API `openById` требует scope spreadsheets. Код работает только с указанным ID. Авторизацию подтверждает владелец. Функция создаёт заголовки, форматирование и `WEBHOOK_SECRET` в Script properties; повторный запуск не меняет ключ и не удаляет заявки.
5. Deploy → New deployment → Web app: Execute as — владелец; Who has access — Anyone. Сама таблица остаётся закрытой. Публичный приёмник принимает записи только с корректной HMAC-подписью, не возвращает данные заявок и не помещает секрет в URL. Сохранить URL `/exec`, не `/dev`.
6. В новом Worker добавить `GOOGLE_SHEETS_WEBHOOK_URL` как переменную и тот же `WEBHOOK_SECRET` под именем `GOOGLE_SHEETS_WEBHOOK_SECRET` как Secret. Секрет не присылать в чат и не добавлять в Git.
7. Применить `0003_google_sheets.sql` через Wrangler migrations до включения канала. До активации проверить приёмник подписанным тестовым запросом. После включения канала проверить тестовую заявку и повтор: одна строка в Sheets, сохранение D1 и успешный email.
8. Включить `GOOGLE_SHEETS_ENABLED=true` в `wrangler.jsonc` и опубликовать. `LEADS_ENABLED` остаётся `true`; остановка рекламы/приёма для настройки не требуется.

## Повторы, старые заявки и изменения

[Подтверждено] D1 хранит независимые `email_status` и `sheets_status`. Ошибка одного канала не блокирует другой. Cron каждые 5 минут повторяет неуспешную доставку. После включения Sheets ранее сохранённые заявки также попадают в очередь; успешные email не отправляются повторно. Приёмник использует блокировку и проверку ID, поэтому повтор после таймаута не добавляет дубль.

[Подтверждено] Заголовки первой строки и колонку «ID заявки» нужно сохранять для автоматической загрузки. Сортировка строк не меняет идентификаторы. Для CRM можно использовать чтение Google Sheets API или выбранный коннектор с доступом к этой таблице. Доступ сотрудникам выдаётся владельцем через «Поделиться».

[Требует уточнения] Перед активацией необходимо зафиксировать ссылку/владельца таблицы, подтвердить разрешения Google и проверить реальную доставку. Автоматическое удаление из D1 по истечении 180 дней не удаляет копии из email и Google Sheets; оператор удаляет их отдельно согласно политике.

[Подтверждено] При обновлении кода Google Apps Script необходимо обновить deployment с сохранением URL `/exec` либо заменить URL в Cloudflare. При сбое Sheets для временного отключения задать `GOOGLE_SHEETS_ENABLED=false` также в Git-конфигурации.
